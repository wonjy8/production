# Production Note

프로젝트·업무 그룹·할 일·일정·타임테이블·자료·멤버·장비를 관리하는 웹 앱입니다.

개인정보와 서버 주소는 소스에 넣지 않고 NAS 설정 및 브라우저 연결 설정으로 관리합니다.

## 워크스페이스 개념

앱의 최상위 워크스페이스는 **홈·자료·데이터베이스** 세 가지입니다.

| 워크스페이스 | 포함하는 내용 |
|---|---|
| 홈 | 프로젝트 목록과 각 프로젝트의 내용 |
| 자료 | 레퍼런스 · 소스 · 포트폴리오 |
| 데이터베이스 | 멤버·장비 · 대여처 · 장소 |

프로젝트를 열어도 홈 워크스페이스에 속하며, 자료 문서는 해당 분류 아래에 속합니다. 탐색 경로는 `홈 / 프로젝트 이름`, `자료 / 소스 / 자료 이름`, `데이터베이스 / 장소`처럼 표시합니다. 갤러리는 자료의 보기 기능이며 별도 분류나 워크스페이스가 아닙니다. 설정과 HUB는 공통 도구입니다.

## 구조

- `production/`: React 프로젝트 화면, 모듈, 레퍼런스 편집기
- `ui/`: 앱 탐색, 설정, 공용 데이터베이스, 스타일
- `worker/`: 웹 앱과 API 게이트웨이를 제공하는 Cloudflare Workers 코드
- `nas/`: NAS에서 실행하는 인증·권한·데이터·파일 서버
- `scripts/`: 빌드와 기능 검증
- `SOURCE.json`: 가져온 사이트 소스의 커밋 정보

## GitHub에서 실행하기

GitHub Pages에서 화면을 실행하고 기존 NAS에 데이터를 저장할 수 있습니다. 최초 NAS 업데이트와 GitHub 설정은 [PAGES.md](PAGES.md)를 따라 진행하세요. `main`에 push하면 `.github/workflows/pages.yml`이 자동 배포합니다.

## 빌드

Node.js와 npm이 필요합니다. 빌드 스크립트는 Bash를 사용하므로 macOS, Linux 또는 Windows의 WSL에서 실행하세요.

```sh
npm ci
npm run build
npm run validate
```

`npm run build`는 React/UI 번들을 재생성하고 `dist/server/`에 Worker 배포 결과를 만듭니다. 번들 파일을 직접 수정하지 말고 `production/`, `ui/`, `worker/index.js`를 수정하세요.

개별 기능 검사는 다음과 같이 실행할 수 있습니다.

```sh
node scripts/test-production.mjs
node scripts/test-auth-gateway.mjs
node scripts/test-timetable.mjs
node scripts/test-schedule-list.mjs
```

## 실행과 데이터 저장

기존 Worker 배포는 `dist/server/index.js`를 Cloudflare Workers 호환 실행 환경에 배포합니다. 새 GitHub Pages 배포는 `npm run build:pages`로 만든 `dist/pages/`를 사용하며, 로그인과 API는 NAS의 `/browser/api/`에서 처리합니다. `.openai/hosting.json`은 기존 ChatGPT Sites의 배포 정보를 보존합니다.

현재 데이터와 파일은 NAS 서버에 저장됩니다. 소스를 이 저장소에 올리는 것만으로 사이트의 호스팅이나 NAS 데이터 위치가 바뀌지는 않습니다.

NAS 구성과 인증 서버 실행 방법은 [nas/README.md](nas/README.md)를 참고하세요. NAS의 실제 `.env`, 데이터베이스, 업로드 파일은 이 저장소에 포함되어 있지 않습니다. 새 환경에 배포할 때는 기존 Worker의 환경 변수를 해당 환경에 별도로 설정해야 합니다.

## 다른 사람의 NAS에 설치

[새 NAS Docker 설치 안내](nas/INSTALL.md)를 따르세요. `python3 scripts/package-nas.py`로 공유할 `dist/production-nas-install.zip`과 기존 서버용 `dist/production-nas-update.zip`을 만듭니다. ZIP에는 소스·설치 스크립트·README만 포함하며 실제 설정·DB·사용자 파일은 포함하지 않습니다. Pages 빌드에도 두 ZIP이 포함됩니다. 배포 후 `/production/production-nas-install.zip`에서 다운로드할 수 있습니다.

## 독립 문서 편집기

WordCraft/WASM 다운로드 없이 문서를 편집합니다. 문서 편집기는 문서를 열 때, 파일 생성 도구와 PDF 도구는 해당 기능을 사용할 때 불러옵니다. 표·글자 서식·쪽 여백·주석·이미지·자동저장과 DOCX 내보내기를 지원합니다. 복잡한 Word 필드 등 지원하지 않는 요소는 원본 XML을 보존하며 읽기 전용으로 표시합니다. Word의 모든 고급 기능을 편집할 수 있다는 의미는 아닙니다.

PDF 내보내기는 브라우저 인쇄를 사용하지 않습니다. 편집 화면의 글자 좌표·글꼴·이미지·표를 PDF 벡터 텍스트와 이미지로 옮겨, 텍스트 선택·복사·검색을 유지합니다. A4·A5·Letter·사용자 지정 용지 크기와 방향·여백을 설정할 수 있으며 화면과 PDF가 같은 페이지 구분을 사용합니다. 확대·축소는 글의 줄바꿈을 바꾸지 않습니다. 화면과 PDF에 동일한 공개 라이선스 글꼴(Liberation, Nanum)을 사용하며 폰트 파일은 문서에서 사용할 때만 불러옵니다. Word 고유 글꼴이 설치되지 않은 경우에도 일관된 배치를 위해 대체 글꼴을 사용합니다. 지원 글꼴에 없는 문자는 누락시키지 않고 내보내기를 중단하여 알려줍니다.

자료 화면은 전체·문서·이미지·영상·링크·오디오·파일 탭과 갤러리·목록·보드 보기를 제공합니다. 문서 탭에서 폴더를 탐색하고, 자료 사이드바 하단의 문서편집기 버튼으로 새 문서를 바로 만들 수 있습니다. 제목은 문서 상단에서 바꾸며 자료 메타데이터에 저장합니다.

## 공용 UI 소스 수정

`ui/page.html`의 `{{source:ui/파일.js}}` 부분은 해당 UI 소스에서 빌드 시 삽입합니다. 서버 로직은 `worker/server.template.js`에서 수정합니다. `npm run build`가 `worker/index.js`와 번들을 생성하므로 생성 파일만 직접 수정하지 마세요.

## 사용자 글꼴과 편집 도구

앱 **설정 → 글꼴**에서 TTF·OTF 파일을 추가·제거합니다(파일당 12MB). 등록 전에 브라우저 표시와 PDF 포함 가능 여부를 검사하며, 문서에서 사용한 글꼴만 불러옵니다. PDF에는 실제 글꼴이 포함되어 다른 기기에서도 텍스트를 선택·검색할 수 있습니다. 등록하지 않은 글꼴이 필요한 경우 내보내기 오류에서 글꼴 추가를 안내합니다.

글꼴 파일과 메타데이터는 기존 자료 API의 권한을 따릅니다. NAS 모드에서는 같은 계정으로 다른 기기에서 불러올 수 있고, 브라우저 저장 모드에서는 현재 브라우저에 저장됩니다. 글꼴 제거는 등록 정보를 숨기며, 기존 문서의 텍스트를 삭제하지 않습니다.

편집기 상단의 연필은 이름 편집, 우측 세 줄 버튼은 문서·속성 패널을 엽니다. 문서에서 용지와 여백·내보내기를, 속성에서 선택한 텍스트·표·이미지의 서식을 조절합니다. 툴바에는 실행 취소·다시 실행과 삽입 도구가 있습니다. 이미지는 자료 검색창에서 선택하면 문서 안에 사본으로 포함되며 원본 자료는 변경되지 않습니다.

## 자료 썸네일 (0.0.11)

자료 갤러리·레퍼런스 표지·문서 이미지 선택창은 최대 640px 썸네일을 화면 근처에서만 불러옵니다. 기기 캐시는 계정·접속 경로와 원본 해시로 구분하며 64MB·400개로 제한합니다. 원본 해시가 바뀌면 새 썸네일을 사용합니다. 문서·영상 등 목록은 아이콘으로 표시하며 원본은 상세 보기·편집·다운로드·문서 삽입 시 가져옵니다. 브라우저 저장 모드는 기기에 있는 원본으로 썸네일을 만들고, NAS 모드는 서버의 작은 WebP만 전송합니다.

NAS는 [0.0.11 적용 안내](nas/UPDATE-0.0.11.md)에 따라 `server.py`, `browser_gateway.py`, `requirements.txt`를 교체하고 컨테이너 이미지를 다시 빌드해야 합니다. `.env`·DB 스키마 변경은 없습니다.

## 통합 자료 휴지통과 DB 분리 (0.0.12)

자료 워크스페이스의 모든 자료·문서·포트폴리오·레퍼런스·소스·아카이브를 하나의 휴지통에서 종류별로 보고 복원하거나 영구 삭제합니다. 아카이브는 팝업 대신 화면에서 열립니다. 멤버 화면은 프로필과 등록 상태, 장비 화면은 보유 장비가 있는 멤버와 장비 추가를 담당합니다.

홈의 완료 일정은 접어 두며 다시 미완료로 전환할 수 있습니다. 모든 일정에서는 위로 스크롤할 때 이전 날짜를 표시합니다. 깃발 할 일은 날짜와 무관하게 이번 주에 남고 완료하면 빠집니다. PC 시간 입력은 오전/오후·시·분으로 나뉘며 분에서 Tab을 누르면 다음 시작/종료 시간으로 순환합니다.

NAS는 [0.0.12 적용 안내](nas/UPDATE-0.0.12.md)에 따라 `resources.py`를 교체한 뒤 컨테이너를 다시 빌드합니다.


## 문서 편집기 (0.0.15)

오른쪽 플로팅 패널의 **문서**에서 용지·여백과 PDF/Word 내보내기를, **속성**에서 선택한 텍스트·표·이미지·도형의 서식을 관리합니다. 탭은 고정되고 내용만 스크롤됩니다. 문단 정렬·줄 간격·앞뒤 여백·들여쓰기·내어쓰기를 지원하고, 목록은 Tab/Shift+Tab으로 최대 5단계까지 조절합니다. 기본 쪽 여백은 Word와 같은 사방 25.4mm입니다. 왼쪽 목차는 제목이 있을 때만 줄 형태로 생성됩니다. 하단에서 페이지·단어 수와 배율을 확인합니다.

삽입 툴바에서 표 크기를 고르고, 이미지(자료/장치)·도형·파일을 추가합니다. 첨부 파일은 자료에 등록되며 문서의 링크를 누르면 열립니다. 자동저장 대기·실패 중에는 창을 닫을 때 브라우저 확인이 뜨고, 편집기 업데이트 알림도 저장을 마친 후 적용합니다. 이번 프런트엔드 업데이트에는 NAS 파일·환경변수·DB 변경이 없습니다.


## 모듈 맞춤 크기와 삭제 버튼 (0.0.14)

모듈 높이는 기본적으로 콘텐츠에 따라 늘고 줄어듭니다. 아래쪽/모서리를 직접 드래그하면 높이를 고정하며, 콘텐츠 맞춤 높이 근처에서는 자석처럼 다시 자동 맞춤으로 돌아옵니다. 아래쪽 핸들 더블클릭 또는 Home 키로도 자동 맞춤을 복원할 수 있습니다. 너비는 기존 반응형 격자 배치를 유지합니다.

모듈 제거 아이콘은 마우스가 모듈 위나 근처에 있을 때 표시합니다. 일정·할일·멤버 등 목록의 제거 아이콘은 해당 행 위에 마우스가 있을 때만 표시하며 붉은색으로 강조합니다. 키보드 포커스와 삭제 확인 상태에서는 계속 표시하고, 터치 화면에서는 항상 사용할 수 있습니다. 일반 창 닫기와 텍스트가 있는 삭제 버튼은 숨기지 않습니다. NAS 변경은 없습니다.
