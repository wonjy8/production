# 제작 기능 통합

Media-Production.zip의 ProjectWorkspace, ProductionTasks, 담당자 선택, 인라인 편집 기능을 현재 앱 안에 통합합니다. 독립 앱이나 별도 iframe은 사용하지 않습니다. 스타일 충돌 방지를 위해 Shadow DOM 내부에서 렌더링합니다.

행사와 제작 프로젝트는 같은 ID와 레코드를 사용합니다. 기존 modules와 알 수 없는 필드를 보존하며 제작 필드만 병합합니다. 자료 파일은 기존 R2 업로드 API를 공유합니다. 자료를 레퍼런스로 저장할 때 파일을 중복 업로드하지 않습니다.

`npm run build:production`으로 React 소스를 worker/production-assets.js로 번들링합니다. 이 생성 파일은 배포 빌드의 입력으로 버전 관리됩니다. `npm run build`와 `npm run validate`로 Worker 산출물을 만듭니다.

첨부 소스에는 사용자의 브라우저 localStorage 및 IndexedDB 데이터가 포함되어 있지 않습니다. 샘플 데이터는 새 앱에 주입하지 않습니다.

## 프로젝트 중심 탐색

사이드바는 홈·자료·데이터베이스의 고정 순서 버튼, 프로젝트 목록, 하단 설정으로 구성합니다. 기존 productions 레코드는 최상위 프로젝트, productionId로 연결된 projects 레코드는 업무 그룹으로 표시합니다. ID와 서버 권한 범위, 파일·공유 원본 연결을 유지하기 위해 기존 저장 필드는 보존합니다. 새 프로젝트의 기본 내용은 defaultBoard가 지정된 customTabs 레코드로 저장하지만 별도 탭으로 표시하지 않습니다. 자료 불러오기와 레퍼런스의 프로젝트 선택·필터도 같은 최상위 목록을 사용합니다.

Hub 템플릿은 `module-hub.js`의 데이터 정의로 관리합니다. 모듈 템플릿은 종류·초기값·분류를, 탭 템플릿은 모듈 템플릿 ID 목록을 참조합니다. `createHubModule`과 `createHubTab`은 매번 새 ID와 독립된 데이터를 만들므로 향후 프로젝트 템플릿에서도 같은 정의를 조합할 수 있습니다.

## 학교·연결 모듈

Hub → 학교 → 학점 계산기에서 과목명, 학점, 성적을 입력합니다. 4.5·4.3·4.0 만점을 선택할 수 있으며 학점 가중 평균을 계산합니다. F는 평점에 포함하고 P·NP는 제외합니다. 성적 미입력과 유효하지 않은 학점은 제외됩니다. 과목과 평점 기준은 모듈 데이터로 저장됩니다.

설정 → 연결에서 Figma 기본 디자인 주소를 저장하거나 해제합니다. Figma 모듈 추가 화면에서 저장된 주소를 재사용하며, 모듈의 ‘기본 연결로 저장’ 버튼으로도 설정할 수 있습니다. 기본 주소는 사용자별로 현재 브라우저에 저장되며 모듈 자체의 주소는 프로젝트·자료 데이터에 저장됩니다. 주소 저장은 Figma OAuth 인증이 아닙니다. Figma 로그인과 비공개 임베드의 세션 유지는 Figma 및 브라우저의 타사 쿠키 정책에서 관리합니다.

## 문서편집기

문서편집기는 Hub의 독립 모듈로 추가하지 않습니다. 파일 카드의 ‘문서편집기로 열기’를 누르면 현재 NAS 또는 브라우저 저장 모드를 유지한 새 탭에서 엽니다. DOCX, TXT, Markdown(텍스트), HTML을 지원합니다. DOCX의 본문·서식·목록·표를 편집할 수 있고, 지원하지 않는 요소는 원본 XML을 보존하는 블록으로 표시합니다. 문서 목록이나 파일 탐색기는 없습니다.

입력 후 0.8초가 지나거나 편집 중 5초가 지나면 같은 파일 ID에 자동저장합니다. Ctrl/Cmd+S, 창 이동, 연결 복구에서도 저장을 시도합니다. 저장 실패 시 탭 안에 편집 내용이 남고, 브라우저의 임시 복구본도 유지합니다. 저장 상태와 재시도 버튼을 표시하며, 다른 편집기가 먼저 수정한 원본은 덮어쓰지 않습니다. 텍스트 파일에는 서식 없이 글 내용만 저장합니다.

텍스트 모듈의 ‘문서편집기로 열기’는 기존 내용을 담은 DOCX 파일을 만들고, 같은 모듈 ID·제목·태그를 유지한 파일 모듈로 전환한 뒤 엽니다. 기존 Wordcraft 모듈도 문서 파일로 전환할 수 있습니다. 이전에 Wordcraft에서 기기로 다운로드한 문서는 파일 모듈로 업로드해서 편집합니다.

NAS에서 기존 파일에 저장하려면 최신 NAS 업데이트 ZIP을 적용해야 합니다. 파일 API는 If-Match 버전과 편집 권한을 확인합니다. 기존 NAS가 자동저장을 지원하지 않으면 편집 화면에서 업데이트 안내를 표시합니다.

기존 WordCraft 0.6.1 배포본과 라이선스는 삭제하지 않았습니다. `npm run build:pages`는 공식 배포본의 SHA-256을 검증하고 포함합니다. 새 문서 UI는 Tiptap, DOCX 및 JSZip을 사용합니다.

## Figma 임베드 코드

Figma 임베드 모듈을 추가하거나 ‘임베드 수정’을 열어 Figma에서 복사한 `<iframe …>` 전체 코드 또는 디자인 링크를 붙여넣습니다. `embed.figma.com`의 새 임베드와 기존 `www.figma.com/embed?url=…` 형식을 지원합니다. 코드에서 검증한 Figma 주소만 모듈에 저장하며, 크기와 테두리는 앱의 모듈 스타일로 표시합니다. 다음 모듈에서 재사용하는 주소 저장은 선택 사항입니다.

임베드 코드는 로그인 정보를 포함하지 않습니다. 로그인 없이 볼 수 있는지는 Figma 파일의 공유 권한과 조직 정책에 따릅니다. 비공개 파일은 Figma 로그인 및 해당 파일의 접근 권한이 필요합니다.

## 모듈 UI와 개요

모듈 추가는 화면 아래에 배치하고, 모듈의 항목 추가는 사진 추가와 같은 작은 하단 버튼으로 표시합니다. 입력란은 편집 중일 때 테두리를 표시합니다. 모듈 삭제는 X 자리의 인라인 확인으로 처리하며 취소, 다른 곳 클릭, 스크롤, Escape로 닫힙니다.

구분선은 상자를 사용하지 않는 전체 너비의 선입니다. 선을 세로로 끌거나 방향키로 옮길 수 있으며, 선 사이의 모듈은 각각 독립된 영역에 배치하고 기존 모듈의 드롭은 해당 영역 안에서만 허용합니다.

프로젝트 개요에는 오늘 할 일과 일정, 홈과 같은 업무 그룹 카드를 표시한 뒤 모듈 추가를 배치합니다. 기존 제작 개요의 기본 보드는 계속 같은 레코드를 사용합니다. 허브에서 삭제한 업무·학교·사역 프리셋은 신규 선택지에서 제외하고 기존 모듈 레코드는 유지합니다.
