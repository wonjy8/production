# Production UI 언어

이 폴더가 앱 UI의 공통 정의와 구현을 소유한다. 화면별 파일은 데이터와 배치 등 도메인 역할을 담당하고, 동일한 UI 요소는 이 폴더에서 가져온다. 실제 적용 목록과 남은 정리는 [INVENTORY.md](INVENTORY.md)를 참고한다.

## 파일과 적용 경로

| 파일 | 책임 |
|---|---|
| `tokens.css` | 색, 크기, 두께, 간격, 반경, 모션의 공통 값 |
| `typography.css` | 제목, 본문, 설명, 상단바 제목·작은 경로·탭 행의 위치·정렬 |
| `page-heading.js` | 일반 DOM·Shadow DOM의 공통 화면 제목 등록과 선택자 |
| `buttons.css` | Squircle 버튼, 변형, 크기, 포커스·비활성 상태 |
| `navigation.css` | 사이드바 항목과 탭의 공통 상태 |
| `surfaces.css` | 모든 둥근 UI 모서리의 Squircle, 화면, 카드, 창, 메뉴, 입력, 구분선 |
| `motion.css` | 모션, 드래그 피드백, 모션 줄이기 |
| `Components.tsx` | React Button, PageHeading, Surface |
| `title-editor.js` | 공통 제목 클릭·입력·저장·취소·실패 재시도, 도메인 권한/저장 어댑터 |
| `features.js` | 셸·React에서 공유하는 임시 기능 활성 상태 |
| `Icon.tsx` / `Icons.tsx` | 이름 기반 아이콘·아이콘 버튼 / 기존 React 호출용 어댑터 |
| `icon-pack.js` | SVG 도형, 문자열 렌더러, 의미별 아이콘 선택 |
| `project-icon-paths.js` | 프로젝트 선택용 확장 아이콘 도형 |

`scripts/build-production.mjs`가 CSS 파일들을 위 순서대로 읽어 일반 UI, React Shadow DOM, 문서 편집 도구의 스타일에 포함한다. 브라우저에서 별도로 중복 로드하지 않는다. `worker/*-assets.js`는 생성 파일이므로 직접 편집하지 않는다. 공통 스타일은 기존 화면 CSS 뒤에서 적용된다.

## 요소의 언어

| 요소 | 정의 및 사용 |
|---|---|
| 화면 | 하나의 작업 맥락. `.ui-screen`은 데스크톱 24px, 모바일 16px/12px 내부 여백. 기존 화면의 도메인 배치는 유지한다. |
| 화면 제목 | 앱 상단바 왼쪽에 20px / 600 / 1.3, 모바일 18px. 경로는 아래 11px 보조색. `PageHeading` 또는 등록된 화면 제목에서 승격하며 본문에 중복하지 않는다. 관련 조작은 본문 상단의 탭/동작 행에 유지한다. 모달·모듈·사용자 문서 제목은 별도. |
| 섹션 제목 | 18px / 600 / 1.35. 설명과 분리하고 영역 시작에 둔다. `.ui-section-title` 사용. |
| 본문·설명 | 본문 14px / 400 / 1.5. 보조 설명 12px / 400 / 1.5. 제목과 버튼 이외에 굵은 글씨를 남용하지 않는다. |
| 글꼴 | OS 시스템 글꼴 → Segoe UI → Noto Sans KR → sans-serif. 임의 외부 폰트 요청 없음. 사용자가 작성하는 문서의 글꼴·크기·굵기는 이 규칙으로 덮어쓰지 않는다. |
| 기본 버튼 | 40px 높이, 텍스트 14px / 500, 좌우 12px, 아이콘 간격 8px. 기본/주요/조용한/위험의 역할을 사용한다. 터치 환경은 신규 공통 버튼 최소 44px. |
| Squircle | 버튼뿐 아니라 카드·입력·탭·사이드바·창·메뉴·썸네일 등 모든 둥근 UI 모서리에 `corner-shape:squircle`을 적용한다. 기존 반경과 크기는 유지하며, 기본 버튼 반경은 12px다. 둥근 사각형과 다른 연속 곡률 코너를 지원 브라우저에서 사용한다. 미지원 브라우저는 각 요소의 기존 둥근 모서리로 폴백한다. clip-path로 포커스·메뉴를 잘라내지 않는다. |
| 아이콘 버튼 | 기본 40×40px, 아이콘 18px. `aria-label`과 툴팁 필수. 원형 버튼을 새로 만들지 않는다. 닫기와 삭제는 다른 의미와 아이콘을 사용한다. |
| 사이드바 | 워크스페이스의 최상위 영역은 프로덕션·자료·설정이며 문서 편집기는 준비 중으로 비활성화한다. 프로덕션 안에는 홈과 프로젝트, 자료 안에는 레퍼런스·소스·포트폴리오 등을 둔다. 자료 안에서 레퍼런스·소스·포트폴리오·모든 자료·아카이브와 멤버·장비·대여처·장소를 구분선으로 나눈다. 레퍼런스·소스·포트폴리오의 분류·태그 하위 탭은 만들지 않는다. 휴지통은 자료 사이드바 하단에 고정한다. 맥락 전환과 하위 탐색. 항목 높이 40px, 왼쪽 정렬, 아이콘+이름. 선택은 배경+굵기로 표시하고 `aria-current`를 사용한다. |
| 탭 | 같은 맥락 내 콘텐츠 전환. 가로 배치, 항목 사이 4px, 높이 40px. 선택은 배경·굵기·상태 속성으로 표현한다. 진짜 ARIA tablist를 만들 때 키보드 화살표·Home/End·연결된 tabpanel도 함께 구현한다. 일반 필터 버튼은 aria-pressed 사용. |
| 창 | 공통 `Modal`의 native dialog 사용. 배경을 차단하고 제목은 위 왼쪽, 닫기는 위 오른쪽. 기본 폭 560px, 내부 24px, 모바일 16px. 최대 높이를 넘으면 내부 스크롤. Esc 닫기, 포커스 복귀 유지. 전체 화면 문서 편집기는 별도 레이아웃. |
| 카드·메뉴 | 카드 내부 16px, 모서리 16px, 1px 경계. 메뉴 내부 6px, 모서리 12px, 그림자. 그림자는 뜬 창·메뉴·드래그 복사본에 사용. |
| 입력 | 높이 40px, 내부 8px/12px, 라벨과 8px. 모바일 입력은 16px로 확대 방지. 오류는 색과 함께 구체적인 텍스트로 제공한다. |
| 강조·색 | 기본은 중립색. 사용자가 고른 accent는 주요 동작·선택에만 사용. 빨강은 파괴 동작·오류, 파랑은 포커스·드롭 위치. 선택·오류를 색 하나로만 알리지 않는다. |
| 여백 | 4/8/12/16/20/24/32px 단계. 같은 묶음 8px, 관련 영역 16px, 상단 제목·경로 사이 2px, 큰 영역 24~32px. |
| 구분선 | 독립 영역의 경계에만 1px 사용. 간격만으로 구분되는 항목에 선을 중복하지 않는다. `.ui-divider` 사용. |
| 모션 | 화면·탭 전환에는 등장·이동·페이드 모션을 사용하지 않고 즉시 표시한다. 제어 상태 피드백 160ms, 창·메뉴 등 일시적인 도구만 필요한 모션을 사용한다. 반복 장식 모션 없음. OS 모션 줄이기를 항상 존중. |
| 드래그앤드롭 | 핸들은 grab/grabbing, 원본은 약하게, 복사본은 그림자, 목적지는 파란 선/외곽선+위치 안내. 드롭 의미·유효성은 기존 도메인 로직 유지. Esc/취소, 잘못된 드롭 시 원상복귀, 터치 지연 드래그 유지. 색상 피드백만으로 이동 방식을 설명하지 않는다. |
| 아이콘 | 24×24 좌표, 기본 표시 18px, 1.75px 선, 둥근 끝·연결. currentColor 사용. 브랜드는 자체 색 예외. 장식 아이콘은 aria-hidden, 의미는 버튼·링크의 이름이 제공한다. 사용자 이모지·사진 아이콘은 별도 사용자 콘텐츠. |

## 코드 사용

```tsx
import {Button, PageHeading, Surface} from '../ui/design-system/Components';
import {Icon} from '../ui/design-system/Icon';

<PageHeading title="자료" actions={<Button icon="plus" variant="primary">추가</Button>}/>
<Button icon="close" variant="quiet" aria-label="창 닫기" title="창 닫기"/>
<Surface><Icon name="file"/> 자료 내용</Surface>
```

일반 DOM은 `.ui-button`, `data-variant="primary"`, `.ui-page-heading`, `.ui-card` 등 동일 클래스를 사용하며 아이콘 문자열은 `iconSVG`를 import한다. 신규 화면에서는 아이콘 팩을 우회해 SVG나 외부 팩을 직접 넣지 않는다. 위험 버튼은 `data-variant="danger"`; 선택은 aria-current/aria-pressed 등 의미에 맞는 속성을 함께 둔다.

기존 화면을 바꿀 때는 먼저 여기의 요소를 재사용한다. 같은 역할의 규칙을 화면 CSS에 복사하지 않는다. 특수한 캔버스·타임테이블·문서 본문은 공통 버튼/색/포커스 규칙을 공유하되 도메인별 치수와 좌표를 유지한다.

## 완료 상태

완료한 프로젝트는 공통 `completion-banner`에 읽기 전용 상태와 **다시 진행**을 표시한다. 프로젝트·업무 그룹의 변경 컨트롤을 비활성화하고 탭 이동·열람·다운로드·사본 만들기는 유지한다. 저장소도 변경을 거절한다. 완료 보존 문서는 원본 편집 대신 사본 편집을 안내한다. 보관함의 완료된 프로젝트 폴더와 숨기기/보이기 버튼은 같은 공통 버튼·글자·여백·Squircle 규칙을 사용하며 화면 진입 모션은 추가하지 않는다.

## 외부 공유

공유 설정은 공통 우측 패널·버튼·필드·구분선을 사용한다. 발급 링크는 읽기 전용 입력란에 표시하고, 공유 중지는 공통 파괴적 동작 색을 쓴다. NAS 외부 열람 화면도 같은 토큰·타이포그래피·Squircle·모션 규칙으로 빌드한다. 외부 내용은 텍스트 노드로 표시하고 프로젝트 편집 컨트롤을 넣지 않는다.

## 워크스페이스 아이콘 레일 — 0.1.5

탐색 레일은 앱 표면 바깥 왼쪽에 독립된 48px 영역으로 둔다. 버튼은 36px Squircle, 아이콘은 문맥 메뉴와 같은 18px이며 세로 간격은 6px이다. 홈·자료 다음 24px 가로 구분선 아래에 문서 편집기를 두고 설정은 하단 12px에 둔다. 비선택은 회색 윤곽, 선택은 검정 채움과 중립 배경이다. 자료 아이콘 앞 문서는 불투명한 바탕으로 뒤 문서의 선을 가린다. 도형은 icon-pack.js에서 가져온다.

같은 아이콘을 다시 누르면 문맥 사이드바를 열거나 닫고, 다른 아이콘은 해당 화면과 사이드바를 연다. 별도 사이드바 버튼은 사용하지 않는다. 닫힌 사이드바의 너비 조절은 포인터·키보드 모두 비활성화하고 탭 순서에서 제외한다. 데스크톱 너비는 사용자 설정을 따른다. 모바일은 같은 네 항목을 하단 탐색에 둔다.

문서 편집기는 오른쪽 본문에서 실행한다. 새 탭 없이 편집하고 다른 화면으로 이동하기 전에 저장을 완료한다. 저장이 막히면 이동하지 않는다. 문서 아이콘으로 돌아오면 열어 둔 문서를 유지하며 새 문서는 문맥 메뉴에서 만든다. 직접 문서 URL을 열었을 때만 독립 편집기 레일을 사용한다. 앱 버전은 설정 → 일반에서 표시한다.

## 상단 제목과 문서 작업 화면 — 0.1.6

앱의 화면 제목은 상단바 왼쪽에 20px·600으로 둔다. 경로는 그 아래 11px 보조색으로 표시하며 기존 이동 동작을 유지한다. 모바일 제목은 18px이다. 일반 DOM과 Shadow DOM은 page-heading.js에 등록한 화면 제목만 승격한다. 본문에 제목을 중복 표시하지 않으며 제목 행의 필터·추가·아이콘 변경 등 조작은 유지한다. 문서 본문, 모달 제목, 모듈 제목과 사용자 작성 제목은 승격 대상이 아니다.

문서 이름은 같은 상단 제목에서 바꾸고 저장 상태와 속성 패널 버튼은 상단바 오른쪽에 둔다. 삽입 툴바는 본문 맨 위 탭 행 위치의 44px 한 줄로 사용한다. 편집 배경은 흰색이고 페이지 경계만 가는 선으로 구분한다. 눈금자는 흰 바탕·옅은 눈금·작은 숫자와 여백 표식을 사용하며 용지 좌표·배율·스크롤을 따른다. 눈금자와 도구 UI는 인쇄·내보내기에 포함하지 않는다.

문서 속성 패널과 모듈 패널은 ui-workspace-panel 표면을 공유한다. 기본 폭 360px, 안쪽 여백 20px, 18px Squircle, 가는 경계선과 그림자 없는 흰 표면을 사용한다. 패널 제목·닫기 버튼 아래에 문서/속성 탭을 두고 선택은 굵기와 밑줄로 표시한다. 작은 화면에서는 패널이 뷰포트를 넘지 않게 맞춘다. 데스크톱은 패널 공간을 예약하고 화면 맞춤 배율을 즉시 계산한다.

## 프로덕션 탐색·고정 사이드바·제목 편집 — 0.1.7

워크스페이스는 최상위 컨테이너다. 탐색 영역은 **프로덕션 → 홈/프로젝트**, **자료 → 레퍼런스/소스/포트폴리오/보관함 등**으로 나눈다. 전체 개요 화면의 이름은 홈이다. 경로는 `프로덕션 / 홈`, `프로덕션 / 프로젝트 이름`, `자료 / 레퍼런스`처럼 표시한다. 영역의 표시 이름은 ui/workspaces.js의 workspaceDefinitions 한 곳에서 가져온다. 기존 ID와 URL은 유지한다.

왼쪽 문맥 사이드바는 제목과 같은 화면 맨 위부터 끝까지 고정한다. 바깥 여백·둥근 카드·그림자를 없애고 오른쪽 1px 경계만 둔다. 목록이 길 때는 내부만 스크롤한다. 제목줄과 본문은 같은 너비·시간·이징으로 사이드바와 함께 좌우 이동한다. 초기 로드에는 이동 모션을 만들지 않는다. 너비 직접 조절은 즉시 반영하고, 닫힌 상태는 포인터·키보드·탭 접근을 막는다. 우측 모듈/속성 패널의 플로팅 표면은 유지한다.

프로젝트·업무 그룹·자료·멤버처럼 사용자가 이름을 정하는 대상은 동일한 title-editor.js를 사용한다. 제목 클릭 → 입력, Enter 또는 다른 곳 클릭으로 저장, Esc로 취소한다. 빈 제목은 거절한다. 저장 중 중복 제출을 합치고 저장 실패 시 입력과 오류를 유지한다. 이동 전에 저장을 기다리고 권한·완료 잠금은 저장할 때 다시 확인한다. 홈·자료·설정 같은 시스템 화면 이름은 고정한다. 각 데이터의 저장소와 권한 규칙은 도메인 어댑터가 담당한다.

문서 편집기는 features.js의 documentEditor=false로 잠시 비활성화한다. 레일·파일 카드·텍스트 변환 버튼은 준비 중으로 표시하고 직접 URL·불러오기·새 문서 생성 경로도 편집기를 열지 않는다. 기존 문서 데이터·원본·다운로드·보관함 기능은 유지한다. 0.1.6 문서 UI 정의는 재작업을 위해 남겨 둔다.

### 열 모듈 (0.1.8)

열은 일반 카드의 예외인 **배치용 컨테이너**입니다. 정의는 [columns.css](./columns.css), 동작은 `production/column-layout.js`, 컨트롤은 `production/ColumnControls.tsx`에서 공통 사용합니다. 2·3·4단을 제공하고, 중첩을 포함한 동시 가로 칸 수는 최대 4입니다. 같은 열에 위아래로 놓인 여러 열 그룹은 가장 넓게 나뉜 그룹을 기준으로 계산합니다.

컨테이너 테두리·배경·내부 패딩은 없습니다. 열 사이에만 16px 간격을 두며, 모듈의 세로 간격은 12px입니다. 구분선은 세로 방향이며 평소 투명, 16px 포인터 접근 영역의 hover 또는 키보드 focus에서 선과 상단 X를 함께 표시합니다. 터치에서는 조작을 발견할 수 있도록 표시합니다. X는 오른쪽 열의 모듈을 왼쪽 열 끝에 순서대로 이어 붙입니다. 마지막 구분선을 지우면 내부 모듈을 부모 흐름에 풀어 놓습니다. 콘텐츠 삭제는 하지 않습니다.

너비는 열 구분선으로 조절하며, 열 내부 카드의 개별 가로 리사이즈는 숨깁니다. 빈 열은 + 또는 모듈 드롭을 받습니다. 중첩 한도를 넘는 열 템플릿은 비활성화합니다. 컨트롤 모서리는 공통 Squircle를 사용하며 아이콘은 공통 icon-pack의 columns-2/3/4·plus·close를 불러옵니다. 화면/탭 진입 모션은 추가하지 않습니다.

### 프로젝트 정체성·일정·할일 (0.1.9)

`project-identity.css`와 `production/project-colors.js`가 프로젝트 색상, 제목 옆 아이콘, 아이콘 선택기를 정의합니다. 색상은 프로젝트/업무 그룹 메타데이터 `iconColor`에 저장하고 일정·할일의 표시에도 같은 값을 사용합니다. 별도 색이 없는 업무 그룹은 상위 프로젝트 색을 사용합니다. SVG 아이콘은 지정색으로 표시하고, 이모지·업로드 이미지는 원래 그림을 유지하면서 연결 일정·할일에 지정색을 적용합니다. 아이콘 변경은 제목 옆에서 한 번만 제공합니다.

선택기 탭 이름은 ‘아이콘 / 이모지 / 업로드’입니다. 이모지는 분류 드롭다운과 항목 테두리 없이 표시하고 검색을 공유합니다. `production/emoji-ko.json`은 Unicode CLDR의 한국어 기본/파생 주석에서 현재 팩의 1,914개 항목만 추출한 이름·검색어입니다. 원문 출처는 unicode-org/cldr-json의 `cldr-annotations-full/annotations/ko/annotations.json`, `cldr-annotations-derived-full/annotationsDerived/ko/annotations.json`이며 라이선스는 `assets/licenses/UNICODE-CLDR.txt`에 있습니다. 네트워크 없이 앱 번들에서 검색합니다. 업로드 안내는 JPG/PNG/WebP, 최대 10MB, 1:1, 저장 256×256px이며 선택 후 자르기·확대 UI를 유지합니다.

`scheduling.css`는 편집창의 중립색 입력 필드와 반복 설정, 일정 표시, 할일 구분선을 정의합니다. 종일 일정은 프로젝트색의 옅은 배경과 대비를 높인 글자색을 사용해 위에 배치합니다. 시간 일정은 배경 없이 왼쪽 색 표시와 오른쪽 오전/오후 시간을 사용하며 시간순으로 정렬합니다. 할일 체크와 행의 강조도 프로젝트 색을 사용합니다. 캘린더는 하단 드래그 또는 ‘높이 늘리기’로 늘리고 프로젝트별 높이를 브라우저에 보관합니다. 보드의 완료는 열이 아닌 아래쪽 일반 목록으로 표시하고, 목록의 시작 전/진행 중/완료 사이는 구분선으로 나눕니다.

반복 UI는 `RepeatFields.tsx`, 규칙·회차 투영·완료 기록·적용 범위는 `recurrence.js`를 공통으로 사용합니다. 매일/매주/매월/매년, 간격, 종료일을 지원합니다. 반복 수정/삭제에는 이번만/이번부터 이후/전체를 선택합니다. 체크 완료는 이번 회차에만 적용하며 다음 회차를 보여주고 완료 기록을 남깁니다. 끝없는 복제 저장 대신 규칙과 예외를 보관합니다. 모든 컨트롤 모서리는 기존 Squircle 원칙을 따릅니다.

### 모듈·시간표·사이드바 정리 (0.1.10)

모듈 카탈로그의 정의와 순서는 `production/module-hub.js` 한 곳에서 가져온다. 기본(메모), 일정(캘린더·타임테이블·일정 목록·할일), 미디어(사진·영상·파일·링크), 나누기(섹션 제목·구분선·2/3/4단 열) 순서다. 제거된 모듈은 `retired-modules.js`에서 내용과 원본 파일 ID를 유지해 메모·파일로 보여 주며, 편집할 때 새 구조를 저장한다. 잠긴 완료 자료는 읽기만으로 저장하지 않는다. 예전 필드 전체는 문자열 스냅샷으로 보존한다.

`module-language.css`는 모듈의 내용 높이를 최소 높이로 정하고 본문 내부 세로 스크롤을 없앤다. 타임테이블은 예외적으로 프레임 안에 시간표를 맞춘다. `ScheduleGrid.tsx`와 `time-grid.css`가 캘린더 주간·일간 및 타임테이블에 공통 적용된다. 1시간마다 선을 그리고 라벨은 공간이 좁으면 2시간 간격으로 표시한다. 좌우 스크롤을 허용하고 트랙패드 확대는 막는다. 이벤트 외곽선은 네 면 모두 같은 옅은 1px 선이다. 색을 직접 정하지 않으면 프로젝트 색을 사용한다.

열 구분선은 전체 그룹 너비의 1/8 간격과 1/3·2/3 위치에 맞춰 이동한다. 내부 중첩 최대 4칸과 콘텐츠 보존 병합 규칙은 유지한다. 공통 아이콘 팩의 열 아이콘은 세로선, 영상은 재생 삼각형, 시간표·일정 목록은 각 구조를 표현하는 선 아이콘이다.

모든 버튼·탭은 호버에 옅은 중립 회색을 사용한다. 추가 액션의 표시 문구는 `+ 대상`으로 줄이고 원래 접근성 이름은 유지한다. 사용자 콘텐츠 제목은 줄이지 않는다. 불러오기는 동일한 목록형 카드, 빈 탭은 `+ 빈 탭`의 가로 정렬을 사용한다. 모든 둥근 모서리에는 기존 Squircle 규칙을 적용한다.

프로젝트 사이드바 아이콘·이름은 프로젝트 지정색을 함께 사용한다. 우클릭 메뉴는 공통 `item-menu.js`를 사용하며 이름 변경은 공통 제목 편집기, 아카이브는 완료 점검, 삭제는 확인창으로 연결한다. 자료 제목은 아이콘 없이 표시하고 사이드바 아이콘은 유지한다. 자료 분류와 멤버 사이에는 구분선 하나만 사용하며 휴지통 위 구분선과 아래 여백을 둔다. 멤버 툴바는 `멤버 → 수 → 정렬 → + 멤버` 순서로 정렬한다.
