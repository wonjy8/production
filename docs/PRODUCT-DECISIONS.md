# 합의된 제품 정책

이 문서는 사용자와의 문답에서 나중에 수정한 결정을 우선하여 정리한다. 구현 범위와 미구현 정책을 구분한다.

## 제작 및 자료

- 제작 계층은 프로젝트 → 업무 그룹. 레퍼런스·소스·포트폴리오는 분리된 보관함으로 유지한다.
- 모든 파일 원본은 보관함에서 관리한다. 프로젝트는 원본을 연결하며 원본 파일을 별도로 소유·저장하지 않는다. 프로젝트에 업로드한 자료도 모든 자료에 표시한다.
- 모든 자료는 사용자가 접근 가능한 전체 자료를 탐색한다. 분류 보관함과 기존 사용 위치는 유지한다.
- 기본은 원본 연결, 독립 편집이 필요하면 사본 생성. 사용처가 줄어도 원본은 보관함에 남긴다.
- 원본을 편집할 때 사용처와 변경 영향을 알리고 원본 수정/사본 편집을 선택하도록 한다.
- 최신 결정에 따라 이전의 '프로젝트로 원본 이동' 및 프로젝트 자체 파일 보관 방식은 폐기한다. 사용 중인 원본은 보관함에서 삭제할 수 없으며 연결을 먼저 해제한다. 사용처가 없는 원본은 휴지통에서 30일 보존한다.
- 개인 등록 자료는 개인 권한, 프로젝트 등록 자료는 해당 위치의 권한을 기본으로 한다. 다른 프로젝트에 연결할 때 권한 부여를 확인하며 승인하지 않으면 접근 권한 없음으로 표시한다. 연결 자체가 원본 권한을 임의로 변경해서는 안 된다.

## 완료 및 재개 — 0.1.2 구현

- 완료 프로젝트는 읽기 전용이다. 사용한 파일은 별도 보존본을 만들고, 프로젝트 연결을 그 보존본으로 전환한다. 진행 중인 다른 프로젝트의 원본은 계속 편집 가능하다.
- 보존본은 보관함의 완료된 프로젝트/프로젝트별 폴더에 보관한다. 숨기면 일반 목록·검색에서 제외하지만 완료 프로젝트에서는 열 수 있다. 보이기를 켜면 탐색에 포함한다.
- 완료 보존본의 내용·제목·설명·태그를 잠근다. 필요하면 사본을 만들어 편집한다. 이전 '동일 원본 전체 잠금' 결정은 보존본 방식으로 대체한다.
- 프로젝트를 재개하면 보존본을 작업용으로 전환한다. 완료 당시 상태를 별도 보관하지 않으며 원본은 계속 보관함에서 관리한다.
- 완료 후 기존 원본에 다른 사용처나 보관함 분류가 없으면 완료 보존본만 남긴다. 참조 중인 다른 원본이나 사용자의 분류 보관 자료는 유지한다.
- 외부 사이트는 URL·제목·설명만 보존한다. 외부 사이트 자체를 내려받거나 고정하지 않는다.

## 외부 공유 — 0.1.3 구현

- 실시간 공유. 링크를 가진 누구나 / 지정 사용자만 선택.
- 선택한 탭·일정·문서·자료만 공개한다. 탭 전체를 공유하면 새 항목도 반영하고, 개별 항목 공유는 선택 항목만 공개한다.
- 링크마다 다운로드 허용 여부와 만료일을 선택하며 기한 없음도 가능하다.
- 프로젝트 완료 시 같은 링크를 보존본으로 전환한다. 재개하면 실시간 공유를 재개한다. 파일 교체도 진행 중인 실시간 공유에 반영한다.
- 사용자·파일 권한은 서버에서 검사해야 한다.

## 제작 템플릿 — 다음 단계

- 업무·모듈·일정을 묶어 저장한다. 담당자와 날짜는 새로 지정한다.
- 모듈 구성은 유지하되 자료·문서 등 연결은 비워서 불러온다.
- 저장할 때 나만 사용 / 팀과 함께 사용 선택. 템플릿과 실제 데이터는 분리한다.

## 0.1.1 구현 범위

원본 업로드 즉시 카탈로그 등록, 기존 파일의 보존적 등록, 같은 ID를 사용하는 연결, 접근 가능한 사용처 안내, 사용 중 원본의 삭제 방지, 독립 사본 생성 및 NAS/브라우저 저장 일치에 집중한다. 공개 공유·새 권한 승인 체계·템플릿 확장은 별도 단계이다. 완료 보존본은 0.1.2에서 구현한다.

## 0.1.2 구현 범위 및 기존 데이터

- NAS 트랜잭션과 브라우저 IndexedDB 트랜잭션에서 보존 파일·메타데이터·프로젝트 연결을 함께 저장한다. NAS는 복사한 파일의 크기·SHA-256을 검사하며, 누락·변경·공간 부족 시 완료 저장을 중단하고 생성 파일을 정리한다.
- 기존 모듈 연결과 공통 기획 데이터는 완료 점검에서 독립 내용으로 고정한다. 준비되지 않은 실시간 연결이 남으면 저장소는 완료를 거절한다.
- 완료된 부모 프로젝트의 업무 그룹도 읽기 전용이다. 먼저 완료한 업무 그룹은 부모가 다시 진행되어도 자체 완료 잠금을 유지한다.
- 완료 자료 숨기기/보이기는 보관함 탐색·문서 검색에 적용되며 프로젝트 안에서는 계속 열 수 있다. 숨기기는 권한 설정을 대체하지 않는다.
- 재개하면 현재 완료 기록을 제거하고 동일 보존본 ID를 작업용 원본으로 사용한다. 다른 프로젝트가 쓰는 이전 원본으로 재연결하지 않는다.
- 새 프로젝트 업로드 중 다른 사용처와 보관함 분류가 없는 기존 원본은 30일 복구 가능한 휴지통으로 이동한다. 사용자가 보관함에 직접 추가한 파일과 출처를 확정할 수 없는 기존 파일은 보존적으로 유지한다.
- 업데이트 전 완료한 프로젝트는 자동으로 파일을 대량 복사하지 않는다. 프로젝트의 **완료 자료 보존본 준비**를 실행하면 현재 남아 있는 자료를 보존한다. 업데이트 이전 시점의 파일 내용을 복구하는 기능은 아니다.
- NAS 운영 서버는 `nas/UPDATE-0.1.2.md`의 파일 교체와 이미지 재빌드가 필요하다. 이전 서버에서는 완료·재개를 막고 업데이트를 안내한다.
- 외부 공개 공유, 새 권한 승인 체계, 제작 템플릿 확장은 이후 단계다.

## 0.1.3 구현 범위 및 공유 제한

NAS에서 발급하는 읽기 전용 실시간 링크를 구현한다. 링크마다 한 프로젝트·업무 그룹·레퍼런스/소스/포트폴리오 위치에서 탭 전체 또는 개별 모듈·일정·할 일·문서/자료 파일을 고른다. 브라우저 전용 데이터는 외부에서 읽을 서버가 없으므로 NAS 연결을 안내한다. 지정 사용자는 등록된 NAS 계정 이메일로 지정하며 공유 화면에서 로그인한다. 새 권한 승인 체계나 초대 메일 발송은 이번 범위가 아니다.

파일 다운로드 설정은 다운로드 버튼과 일반 원본 전달을 제어한다. TXT/DOCX 내용과 미디어/PDF 열람은 제공하지만 화면에 공개한 내용의 저장을 완전히 막지 못한다. 만료·중지·현재 발급자 권한·현재 파일 접근·지정 계정은 파일 요청에도 검사한다. 공유에서 다른 위치·멤버 개인정보·권한·전체 데이터·완료 기록을 반환하지 않는다. 구형 실시간 모듈/기획 연결은 독립 사본 전환 후 공유한다.

완료 시 선택 파일 ID를 해당 프로젝트의 보존본으로 함께 전환한다. 같은 원본을 사용하는 다른 프로젝트 공유는 유지한다. 재개 시 현재 보존본을 그대로 사용한다. 운영 NAS의 8개 파일 교체·이미지 재빌드·`/public/` HTTPS 경로 전달이 필요하다. 제작 템플릿과 새 권한 승인 체계는 다음 단계다.

## 0.1.4 UI 수정 및 전체 기획 점검

최신 합의를 코드와 대조한 상태는 PRODUCT-AUDIT-0.1.4.md에 기록한다. 전체 구현 완료로 간주하지 않는다. 제작 템플릿 확장과 다른 프로젝트 연결 시 새 권한 승인 흐름이 남아 있다. 이번 UI는 사이드바 내부 아이콘 레일, 선택 시 채움, 겹친 문서 자료 아이콘, 구분선 아래 문서 편집기, 최하단 설정을 사용한다. 앱 버전은 설정 일반에서만 표시한다.

## 2026-10-16 — 명시적 열 모듈

- 모듈은 블록처럼 세로 흐름으로 배치하고, 옆 배치는 2·3·4단 열 컨테이너를 명시적으로 사용한다.
- 중첩을 허용하되, 중첩을 포함한 동시 가로 칸 수는 최대 4이다. 바깥 2단의 한쪽을 3단으로 나누면 총 4칸이다.
- 열 컨테이너는 일반 모듈 카드와 달리 테두리·내부 패딩 없이 열 사이 간격만 사용한다.
- 열 사이 구분선과 상단 X는 포인터가 가까이 오면 함께 나타난다. 구분선 삭제는 콘텐츠 삭제가 아니다. 오른쪽 열의 모듈을 바로 왼쪽 열의 마지막 모듈 아래에 기존 순서대로 붙인다. 마지막 구분선 삭제 시 열 구조만 풀어 놓는다.

## 2026-10-16 — 프로젝트 색상과 반복 일정·할일

- 프로젝트와 업무 그룹의 아이콘은 상단 제목 옆에서 변경한다. 색상을 저장해 아이콘(SVG)·일정·할일을 연결한다. 업무 그룹의 별도 색이 없으면 상위 프로젝트 색을 사용한다.
- 종일 일정은 상단의 옅은 프로젝트색 배경, 시간 일정은 왼쪽 작은 색 표시와 오른쪽 시간을 사용한다. 캘린더는 아래로 늘릴 수 있다.
- 보드의 완료 항목은 열에서 제외하고 보드 아래의 일반 목록으로 표시한다. 목록의 세 상태 사이에는 구분선을 둔다.
- 반복 수정·삭제는 사용자가 선택한 **이번만 / 이번부터 이후 / 반복 전체** 세 범위를 제공한다. 반복 완료 체크는 이번 회차만 완료하고 이력을 남긴 뒤 다음 회차를 표시한다.
- 이모지 탭은 개수와 드롭다운·항목 테두리를 없애고 한글/영문 검색을 제공한다. 사진 탭 이름은 업로드이며 업로드 영역에 형식/용량/비율/저장 규격을 표기한다.

## 2026-10-16 — 0.1.10 모듈과 사이드바

- 제거 모듈의 기존 내용은 삭제하지 않는다. 사용자가 선택한 ‘내용 보존’에 따라 메모·파일로 전환하고 원본 ID와 전체 필드 스냅샷을 유지한다. 완료 잠금 자료는 보기만으로 다시 저장하지 않는다.
- 모듈 순서는 기본(메모), 일정(캘린더·타임테이블·일정 목록·할일), 미디어(사진·영상·파일·링크), 나누기(섹션 제목·구분선·열)다.
- 열 너비는 1/8 간격과 1/3·2/3에서 맞춘다. 기존 최대 4칸 중첩 및 오른쪽 내용을 왼쪽 아래로 유지하는 병합은 그대로다.
- 일반 모듈은 내부 세로 스크롤 없이 내용 높이 이상으로 표시한다. 타임테이블은 최소 조작 영역을 남기고 모듈 프레임에 맞춰 시간표를 늘이거나 줄인다. 캘린더는 월/주/일 보기를 제공한다.
- 타임테이블의 일정 포함/제외 설정은 해당 모듈에서 만든 일정에 적용한다. 제외는 캘린더·통합 일정 목록에서만 숨기며 데이터를 삭제하지 않는다. 다른 프로젝트에서 가져와 표시하는 일정의 원본 노출은 바꾸지 않는다.
- 프로젝트 사이드바 우클릭의 아카이브는 기존 완료 점검과 보존 절차를 사용한다. 이름은 공통 제목 편집기, 삭제는 확인창으로 연결한다.
- 자료 제목 아이콘은 숨기고 사이드바는 유지한다. 멤버 툴바는 ‘멤버 / 수 / 정렬 / + 멤버’ 순서다. 추가 액션은 ‘+ 대상’으로 줄이며 원래 접근성 이름과 사용자 작성 콘텐츠는 유지한다.
