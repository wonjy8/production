- `npm run build`, `npm run validate`, `npm run build:pages` 통과. 화면·Pages `version.json`의 릴리스 버전은 `0.1.2`다.
- JavaScript 검사 17개 통과: production, auth-gateway, grade-calculator, figma-connection, pages-route, document-library, planning, resource-schema, completion-summary, completion-policy, module-placement, module-transfer, task-status, icons, module-tabs, photo-editor, unified-projects.
- `.venv/bin/python -W ignore -m unittest discover -s nas -p 'test_*.py' -q`: 40개 통과. 완료 후 독립 파일, 파일/메타데이터/업무/하위 그룹 잠금, 누락 파일의 트랜잭션·생성 파일 롤백, 같은 ID 재개, 다른 프로젝트 원본 독립성, 기존 완료 자료의 명시적 준비, 부모 재개 후 자체 완료 업무 그룹 잠금을 검증했다.
- `CHROMIUM_PATH=/usr/bin/chromium NAS_PYTHON=$PWD/.venv/bin/python .venv/bin/python scripts/test-completion-browser.py`: 브라우저 저장·임시 HTTPS NAS 모두 통과. 실제 개요 수정/완료 점검 UI에서 완료, 서버가 반환한 보존본 ID의 화면 반영, 보존본 내용/속성 API 잠금, 다른 프로젝트 원본 수정, 숨기기/보이기 및 프로젝트별 폴더, 완료 문서의 사본 전용 편집, 같은 ID 재개와 현재 완료 기록 제거를 검증했다.
- 같은 환경에서 `scripts/test-original-catalog-browser.py`: 브라우저 저장·NAS 모두 통과. 기존 원본 등록·숨긴 사용처·삭제 보호·사본 생성·문서 수정 선택·독립 파일·연결 해제·휴지통 복원·모바일 가로 폭 회귀를 확인했다.
- 완료 프로젝트의 문서가 기본 문서 목록/검색에서 제외되고, 보이기를 켜면 완료된 프로젝트/프로젝트별 폴더에 중복 없이 표시되는 것을 모델 검사로 확인했다.
- 실시간 모듈과 공통 기획 데이터가 완료 후 독립 내용이 되는 것을 검사했다. 저장소는 고정되지 않은 연결이 남은 완료 요청을 거절한다.
- 공유 디자인 CSS 구문과 `git diff --check` 통과. NAS 업데이트 ZIP의 다섯 구현 파일 및 UPDATE-0.1.2.md가 소스와 동일하고 비밀·데이터 파일이 포함되지 않았음을 확인했다.

운영 NAS에 접속해 설치한 것은 아니다. 브라우저 저장과 격리된 NAS에서 검증했으며 운영 적용은 [NAS 안내](../nas/UPDATE-0.1.2.md)에 따른 파일 교체·이미지 재빌드가 필요하다. 공개 링크 공유·새 권한 승인 체계·템플릿 확장은 이번 범위에 포함하지 않는다.

기존 `test-resource-database-browser.py`의 예전 전용 속성 가정과 현재 일반 속성의 불일치는 [0.1.1 검증 기록](0.1.1-VALIDATION.md)에 남아 있다. 이번에는 해당 검사를 재실행하거나 통과했다고 처리하지 않았다.
