# 0.1.1 보관함 원본 관리

기존 최신 NAS에서 업데이트하는 경우 실제 실행 파일 변경은 **resources.py**, **server.py** 두 개입니다. 반드시 함께 교체하세요. `.env`, `data/`, `compose.yaml`, 계정 키와 기존 데이터베이스는 유지합니다. DB 스키마·환경변수·의존성 변경은 없습니다.

## 적용

1. 기존 NAS 프로젝트의 data 폴더(파일·DB·account.key 포함)를 백업합니다.
2. 업데이트 ZIP에서 `resources.py`, `server.py`를 기존 NAS 프로젝트 폴더에 덮어씁니다. 이 안내문도 함께 보관할 수 있습니다.
3. 기존 프로젝트 폴더에서 실행합니다.

```sh
sh update.sh
```

이 스크립트는 실행 중인 SQLite DB를 백업하고 `docker compose up -d --build`로 이미지를 재빌드합니다. DSM Container Manager에서는 기존 프로젝트의 이미지를 다시 빌드하고 컨테이너를 다시 생성하세요. 단순 재시작만으로는 새 Python 코드가 반영되지 않습니다.

## 검증

- 앱에서 사용하지 않는 테스트 파일을 추가한 뒤 모든 자료에 즉시 나타나는지 확인합니다.
- 같은 파일을 두 프로젝트에 '기존 자료 연결'로 추가합니다. 사용처에 두 프로젝트가 표시되고 원본 ID는 하나인지 확인합니다.
- 사용 중인 원본의 휴지통 동작이 차단되는지 확인합니다. 숨긴 탭의 연결도 보호합니다.
- 사본을 만들면 별도 파일로 추가되고 원본은 유지되는지 확인합니다.
- 프로젝트의 연결을 모두 해제해도 원본은 보관함에 남습니다. 이제 원본을 휴지통으로 이동하고 복원할 수 있어야 합니다.
- 공유 중인 문서를 열어 원본 수정/사본 편집 선택을 확인합니다.

기존 파일은 물리적 위치와 ID를 유지하며 카탈로그에 등록합니다. 원래 파일명이 남지 않은 미등록 파일은 ID로 표시될 수 있으며 속성에서 이름을 지정할 수 있습니다. 기존 메타데이터·계정·권한은 덮어쓰지 않습니다. 이전 버전에서 휴지통으로 보냈지만 활성 사용처가 남은 원본은 조회 시 다시 활성화하여, 연결된 자료가 숨겨지거나 만료 삭제되지 않게 합니다. 영구 삭제 기록은 자동 복원하지 않습니다.

프런트엔드 배포는 NAS 업데이트를 실행하지 않습니다. 운영 NAS에서 위 작업을 마쳐야 즉시 등록과 서버 삭제 보호가 적용됩니다. 완료 프로젝트 보존본·외부 공개 공유·새 권한 승인 모델·제작 템플릿은 이번 단계에 포함되지 않습니다.
