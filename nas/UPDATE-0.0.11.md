# 0.0.11 이미지 썸네일 업데이트

자료 목록은 최대 640px WebP 썸네일을 사용합니다. 원본은 상세 보기·편집·다운로드·문서 삽입 시 읽습니다. 영상·문서 등은 목록에서 파일 종류 아이콘을 사용해 원본 요청을 피합니다.

## 교체할 파일

기존 NAS 프로젝트 폴더에서 다음 세 파일을 새 버전으로 교체하세요.

- `server.py`: 인증·파일 권한 확인 후 썸네일을 생성하고 `/data/thumbnails/`에서 재사용합니다.
- `browser_gateway.py`: 브라우저에 썸네일 응답 헤더를 전달합니다.
- `requirements.txt`: 이미지 처리 의존성 `Pillow==12.2.0`을 추가합니다.

`production-nas-update.zip`을 별도 폴더에 푼 뒤 위의 세 파일만 기존 프로젝트 폴더에 덮어쓰면 됩니다. 기존 `.env`, `data/`, `compose.yaml` 및 다른 NAS 설정은 유지하세요. 새 환경변수나 DB 스키마 변경은 없습니다.

## 적용

기존 NAS 프로젝트 폴더에서 다음을 실행하세요.

```sh
sh update.sh
```

이 스크립트는 실행 중인 DB를 백업한 뒤 `docker compose up -d --build`로 컨테이너를 다시 만듭니다. 단순 재시작으로는 Pillow가 설치되지 않습니다.

Container Manager를 사용한다면 프로젝트 소스를 교체하고 이미지를 다시 빌드하여 컨테이너를 재생성하세요. 기존 `./data:/data` 볼륨은 그대로 유지합니다.

## 확인

1. 앱을 새로고침하고 자료의 갤러리를 엽니다.
2. 개발자 도구 Network에서 목록 이미지가 `ref-files/<id>?thumbnail=1`로 요청되고 `image/webp`로 반환되는지 확인합니다.
3. 같은 화면을 새로고침하면 기기에 저장된 썸네일을 사용합니다. 이미지를 열거나 문서에 삽입할 때만 쿼리 없는 원본 요청이 생깁니다.
4. 자료 파일을 교체하면 내용 해시가 바뀌어 새 썸네일이 표시됩니다.

기기 캐시는 계정·접속 경로별로 구분하며 최대 64MB·400개, 최대 30일 보관합니다. 원본 해시를 알 수 없는 이전 자료는 5분 후 재검증합니다. 브라우저가 저장소를 비우면 자동으로 다시 만듭니다. NAS 썸네일은 최대 약 256MB로 정리하며, 한 번에 최대 두 이미지를 생성합니다.

NAS 프로젝트의 `data/thumbnails/`는 재생성 가능한 캐시입니다. 원본 `data/files/`나 DB를 수정하지 않습니다. 0.0.10으로 앱을 롤백할 때도 기존 원본·DB는 그대로 사용할 수 있습니다.
