# 0.1.2 완료 프로젝트 보존본 및 재개

0.1.1 NAS에서 업데이트할 때 다음 **5개 파일을 함께 적용**합니다.

| 파일 | 변경 |
| --- | --- |
| `completion.py` | 새 파일. 완료 보존본 복사·검증, 읽기 전용 보호, 재개 처리 |
| `server.py` | 저장 트랜잭션에 완료 처리 연결, 보존 파일 수정 차단, 기능 버전 응답 |
| `resources.py` | 보존본 메타데이터·삭제 잠금, 독립 자료 ID, 원본 보관 정책 |
| `browser_gateway.py` | 앱에 완료 보존본 기능 지원 알림 |
| `Dockerfile` | 이미지에 새 `completion.py` 포함 |

`.env`, `data/`(파일·DB·account.key), `compose.yaml`은 유지합니다. DB 스키마·의존성·환경변수 변경은 없습니다. 0.1.1보다 오래된 서버는 업데이트 ZIP의 실행 소스 전체를 적용하되 설정과 데이터는 유지하세요.

## 적용

1. 기존 `data/` 전체를 백업합니다. 보존본에는 사용한 파일만큼 추가 디스크 공간이 필요합니다.
2. 앱의 NAS 업데이트 ZIP을 내려받아 위 5개 파일을 기존 NAS 프로젝트 폴더에 덮어씁니다.
3. 기존 프로젝트 폴더에서 실행합니다.

```sh
sh update.sh
```

스크립트는 SQLite DB를 백업한 후 `docker compose up -d --build`를 실행합니다. DSM Container Manager에서는 기존 프로젝트의 이미지를 재빌드하고 컨테이너를 다시 생성하세요. 단순 재시작으로는 새 코드가 반영되지 않습니다.

## 검증

- NAS 주소의 `/health`에서 `features.completionCopies`가 `1`인지 확인합니다.
- 테스트 파일을 진행 중인 두 프로젝트에 연결하고 한 프로젝트를 완료합니다. 완료 프로젝트에는 읽기 전용 표시가 나타나고, 연결 파일 ID가 별도 보존본 ID로 바뀌어야 합니다.
- 진행 중인 프로젝트에서 이전 원본을 수정해도 보존본 내용은 바뀌지 않아야 합니다. 보존본의 원본 수정·속성 저장·삭제는 차단되어야 합니다.
- 자료에서 **완료 자료 보이기**를 누르면 **완료된 프로젝트 → 프로젝트 이름**으로 탐색할 수 있어야 합니다. 숨기면 일반 목록·문서 검색에서 제외됩니다. 완료 프로젝트 안에서는 계속 열 수 있습니다.
- 완료 보존 문서에는 **사본을 만들어 편집**이 표시되어야 합니다.
- **다시 진행**을 누르면 같은 보존본 ID를 수정할 수 있고 현재 완료 기록은 제거됩니다. 다른 프로젝트의 원본은 그대로 유지되어야 합니다.
- 업데이트 이전 완료 프로젝트는 **완료 자료 보존본 준비**를 실행하세요. 이 작업은 현재 남아 있는 파일을 보존하며 과거 파일 내용까지 복원하지는 않습니다.

파일 누락·동시 변경·NAS 디스크 공간 부족으로 보존에 실패하면 저장소의 완료 상태와 복사 작업을 함께 취소합니다. 오류를 해결한 뒤 재시도하세요. 새 프로젝트 업로드 원본은 다른 사용처와 보관함 분류가 없으면 30일 복구 가능한 휴지통으로 옮기며, 기존 출처 불명 파일과 보관함 직접 등록 파일은 유지합니다.

웹 프런트엔드 자동 배포는 운영 NAS를 업데이트하지 않습니다. 운영 NAS에서 이 절차를 마쳐야 완료·재개 기능을 사용할 수 있습니다. 기존 파일을 바꿔 사용하는 공개 링크 공유와 제작 템플릿 확장은 이번 릴리스에 포함되지 않습니다.
