# NAS 서버 운영·업데이트

다른 사람의 NAS에 처음 설치하려면 [새 설치 안내](INSTALL.md)를 따르세요. `install.sh`와 `configure.py`가 초기 설정을 준비합니다. 기존 NAS에는 `update.sh`를 사용합니다.

Supabase와 SMTP를 사용하지 않습니다. 계정·세션·권한·제작 데이터·파일은 기존 NAS에 보관합니다.

## 업데이트

보관함 원본 등록과 사용 중 삭제 보호는 [0.1.1 적용 안내](UPDATE-0.1.1.md)를 참고하세요. `resources.py`와 `server.py`를 함께 교체하고 이미지를 다시 빌드합니다.

0.0.6 통합 자료 DB 적용 파일과 확인 방법은 [버전별 안내](UPDATE-0.0.6.md)를 참고하세요.

1. NAS의 기존 data 폴더를 스냅샷 등으로 백업합니다. account.key 파일이 있다면 함께 보관합니다.
2. 이 패키지의 파일을 기존 프로젝트 폴더에 덮어씁니다. 기존 `.env`와 `data`는 그대로 유지합니다. 패키지에는 둘 다 포함하지 않습니다.
3. Container Manager에서 기존 프로젝트의 이미지를 다시 빌드하고 실행합니다. 단순 재시작만으로는 파일 변경이 이미지에 반영되지 않습니다.
4. NAS 외부 포트는 8788, 컨테이너 내부는 8787입니다. 역방향 프록시의 대상 포트는 8788로 유지합니다. HTTPS 주소와 NAS_API_TOKEN, NAS_UID, NAS_GID는 기존 값을 유지합니다.

## 첫 최고관리자 생성

첫 계정으로 로그인하면 최고관리자가 됩니다. NAS 설정 코드가 있어야 첫 계정을 만들 수 있습니다. 터미널이나 이메일 인증은 필요 없습니다.

1. 앱의 회원가입 → 첫 관리자 설정을 누르고 설정 값을 복사합니다.
2. DSM File Station에서 기존 프로젝트의 `.env`를 편집해 복사한 `ADMIN_SETUP_CODE=...` 줄을 추가합니다. 기존 값은 유지합니다. 파일을 편집할 수 없으면 내려받아 텍스트 편집기로 수정한 뒤 같은 이름으로 업로드합니다.
3. 아래 업데이트 파일을 같은 프로젝트 폴더에 덮어씁니다. `data` 폴더와 기존 `.env`는 삭제하지 않습니다.
4. Container Manager에서 기존 프로젝트를 다시 빌드하고 실행합니다. 새 환경변수가 적용되도록 컨테이너를 다시 만들어야 합니다.
5. 앱에서 회원가입으로 돌아갑니다. NAS의 `ADMIN_EMAIL`에 설정한 이메일, 원하는 비밀번호, `=` 뒤의 초기 설정 코드로 가입합니다. 비밀번호는 최소 8자이며 숫자·특수문자를 각각 포함합니다. 점(.)도 허용됩니다.
6. 가입 후 바로 앱을 사용할 수 있습니다. 인증 앱이나 2단계 인증은 요구하지 않습니다.

초기 설정 코드는 첫 계정을 만든 뒤 재사용할 수 없습니다. `.env`에서 해당 줄을 지워도 계정은 유지됩니다. 설정 페이지를 닫았다면 `.env`의 `=` 뒤 값을 회원가입 코드에 넣으면 됩니다. 이미 계정이 있으면 기존 계정으로 로그인하며 등급을 자동으로 바꾸지 않습니다.

터미널을 사용할 수 있다면 `python setup_admin.py`로도 첫 계정을 만들 수 있습니다.

첫 계정의 이메일과 이름은 NAS의 비공개 `.env`에 `ADMIN_EMAIL`, `ADMIN_NAME`으로 설정합니다. 기존 개인 멤버와 연결하려면 `ADMIN_MEMBER_ID`를 지정하거나 정확히 같은 이메일을 사용합니다. 기존 멤버의 이름·연락처는 덮어쓰지 않습니다. 이미 초기 계정이 있으면 기존 DB를 사용하며 이 설정은 필요하지 않습니다.

## 다른 사용자 가입

데이터베이스 → 멤버·장비 → 멤버의 계정에서 개인 멤버와 로그인 이메일을 지정해 초대 링크를 만듭니다. 해당 사람에게 직접 전달합니다. 초대받은 사용자는 이메일(로그인 ID), 비밀번호, 초대 코드로 즉시 가입합니다. 메일을 보내거나 이메일 소유를 인증하지 않습니다. 링크는 해당 멤버와 이메일에 묶여 있고 3일 동안 한 번만 사용할 수 있습니다. 기본 등급은 일반입니다. 사용자 등급은 최고관리자만 변경합니다.

## 비밀번호 재설정

최고관리자는 데이터베이스 → 멤버·장비 → 멤버의 계정 → 비밀번호 재설정에서 해당 사용자에게 줄 일회용 코드를 만듭니다. 사용자는 로그인 화면의 비밀번호 찾기에서 이메일, 코드, 새 비밀번호를 입력합니다. 코드 유효시간은 1시간이며 한 번만 사용할 수 있습니다. 비밀번호 재설정 후 기존 세션은 모두 만료됩니다.

최초 최고관리자가 비밀번호를 잊었을 때는 NAS 컨테이너 터미널에서 아래 명령을 실행합니다. 기존 인증 앱은 유지됩니다.

```sh
python setup_admin.py --reset-password
```

## 데이터·보안

프로덕션 조회 범위와 탭별 보기·추가·수정·삭제 권한은 서버에서 검사합니다. 다른 멤버 개인정보는 최고관리자만 수정할 수 있습니다. 관리자는 장비와 전체 설정을 수정할 수 있습니다. 본인 개인정보는 설정 → 내 계정에서 수정합니다. 호칭은 로그인 계정의 속성이 아닌 멤버 정보이며, 데이터베이스 → 멤버·장비에서 최고관리자·관리자만 수정합니다. 일반·고급·운영자는 본인의 호칭도 수정할 수 없습니다. 사용자와 멤버는 같은 멤버 정보로 표시합니다. 계정이 없는 개인 멤버는 미등록으로 표시하며 계정에서 초대합니다. 로그인 이메일·등급·정지 상태는 데이터베이스 → 멤버·장비 → 멤버의 계정에서 최고관리자가 수정합니다. 로그인 이메일 변경 시 해당 계정의 세션이 만료됩니다. 연락 이메일과 로그인 이메일은 별개로 유지합니다.

비밀번호는 Argon2id로 해시하고 세션·초대 코드의 원문은 DB에 저장하지 않습니다. 인증 앱 키는 data/account.key로 암호화됩니다. 이 파일과 DB를 함께 백업합니다. HttpOnly/Secure 쿠키, 로그인 시도 제한, 서버 권한 검사와 감사 기록은 유지됩니다.

SMTP 환경변수는 더 이상 필요하지 않습니다. 기존 `.env`에 남아 있어도 사용하지 않습니다. 사이트의 ChatGPT 접근 제한은 현재 유지되어 있습니다. 다른 사용자의 외부 접속을 허용하려면 사이트 접근 정책을 별도로 조정해야 합니다.

## GitHub Pages 연결

[NAS 설치·HTTPS 연결 안내](INSTALL.md)의 업데이트 절차를 따르세요. `PAGES_ORIGINS`에 실제 Pages 원본 주소를 기존 `.env`에 추가하고 새 `browser_gateway.py`를 포함해 컨테이너를 재빌드합니다. 이 값이 비어 있으면 브라우저 직접 접속은 비활성화됩니다. 기존 Worker API와 NAS 데이터는 유지됩니다.

## 0.0.1: 자료 휴지통

이번 버전의 서버 변경 파일은 `server.py`와 `access.py`입니다. 기존 `.env` 설정을 변경하지 않고 업데이트 패키지를 기존 프로젝트 폴더에 덮어쓴 다음 `sh update.sh`를 실행하거나 Container Manager에서 이미지를 다시 빌드합니다.

자료는 휴지통으로 이동한 시점부터 30일간 보관됩니다. NAS 시작 후 및 매시간 만료 자료를 정리하고, 자료 목록을 불러올 때도 만료 여부를 확인합니다. 휴지통 안의 자료를 편집해도 보관 기한은 연장되지 않습니다. 복원하면 삭제 기한이 해제됩니다. 자료 사이드바의 휴지통에서 항목을 여러 개 선택해 복원하거나 30일 이전에 영구 삭제할 수 있습니다. 영구 삭제는 되돌릴 수 없으며 다른 자료·프로젝트·완료 아카이브에서 사용하는 파일은 유지됩니다.
