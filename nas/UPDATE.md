# NAS 업데이트 — 0.1.11

공유 화면을 웹 배포에서 자동 갱신하는 방식으로 전환합니다. NAS의 정적 `share-view.html`은 더 이상 사용하지 않습니다. 이 서버 업데이트를 한 번 적용하면 이후 공유 화면·디자인 수정 때문에 NAS를 재빌드할 필요가 없습니다. NAS API 자체를 변경하는 향후 릴리스에는 별도 서버 업데이트가 필요할 수 있습니다.

## NAS 0.1.10 기준 교체 ZIP

- `public_gateway.py`: 공용 화면 HTML만 Pages에서 받아 NAS 주소에서 제공합니다. 5분간 메모리에 캐시하고 다시 확인하며 네트워크 일시 실패 시 마지막 공용 화면을 유지합니다. 최초 로딩 실패 시 503으로 재시도를 안내합니다.
- `Dockerfile`: NAS 이미지에서 `share-view.html` 복사를 제거합니다.
- `update.sh`: 재빌드 성공 후 더 이상 쓰지 않는 로컬 `share-view.html`을 제거합니다.
- `README.md`, `UPDATE.md`: 최신 운영·적용 안내입니다.

기존 설치 폴더에 위 파일을 덮어쓰고 실행합니다.

```sh
sh update.sh
```

기존 스크립트는 DB 백업 후 이미지를 재빌드하고 컨테이너를 재생성합니다. `.env`, `data/`, DB, 계정 키, 기존 포트와 HTTPS 프록시는 유지합니다. DB 스키마·의존성 변경과 필수 환경변수 추가는 없습니다. Container Manager를 사용해도 같은 폴더에서 재빌드·재생성하고, 성공 후 이전 `share-view.html`을 삭제할 수 있습니다.

## 개인정보와 연결

- 공유 URL과 공유 토큰은 기존 NAS 주소에 유지합니다. Pages로 리디렉션하지 않습니다.
- NAS가 요청하는 주소는 `https://wonjy8.github.io/production/share-view.html`이라는 공용 화면 파일 한 개입니다. NAS에서 이 주소로 나가는 HTTPS 연결이 필요합니다.
- 화면 파일 요청에 공유 토큰·파일·제목·로그인 정보·쿠키·NAS 서비스 토큰을 넣지 않습니다. HTTPS 검증을 유지하며 다른 주소로의 리디렉션도 따라가지 않습니다.
- 계정 로그인, 지정 사용자, 만료·중지, 공유 선택 범위, 미리보기·다운로드 권한은 계속 NAS에서 검사합니다. 브라우저의 데이터 요청도 NAS의 동일 출처로만 보냅니다.
- 자신의 웹 배포를 운영하는 경우에만 컨테이너 환경의 `PUBLIC_VIEWER_URL`을 해당 배포의 공용 HTTPS 화면 주소로 지정합니다. 기본 설치에서는 설정할 필요가 없습니다.

확인: 컨테이너 정상 실행, 기존 계정 로그인, 자료 다운로드, 기존 공유 링크의 익명/지정 사용자 열람과 다운로드 제한을 확인합니다. 웹 화면은 새 배포 후 최대 약 5분 내 최신본을 사용합니다. 운영 NAS에 자동 접속해 파일을 바꾸는 작업은 수행하지 않습니다.

현재 NAS 버전이 다르거나 기준을 모르면 최신 전체 `production-nas-update.zip`의 서버 실행 파일을 함께 적용하세요. 먼저 `.env`와 `data/` 전체를 백업하고 같은 폴더에 코드만 덮어쓴 뒤 `sh update.sh`를 실행합니다. 기존 설치에 신규 설치용 `install.sh`를 실행하지 않습니다. Pages의 `/browser/api/`, 공유의 `/public/` HTTPS 전달 설정은 [INSTALL.md](INSTALL.md), 계정 운영은 [README.md](README.md)를 참고하세요.
