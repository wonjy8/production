# 0.0.6 자료 데이터베이스 업데이트

기존 NAS 프로젝트 폴더에서 아래 네 파일을 이번 버전 파일로 교체/추가합니다.

- `server.py`: 기존 저장 API에 통합 자료 등록과 파일 보존 연결을 추가합니다.
- `resources.py` (새 파일): 자료 목록, 속성 수정, 기존 자료 등록, 권한 및 버전 충돌 검사를 구현합니다.
- `schema.sql`: 기존 DB에 `resource_records` 테이블과 인덱스를 추가합니다. 기존 테이블이나 파일은 지우지 않습니다.
- `Dockerfile`: 새 `resources.py`를 이미지에 포함합니다.

## 적용

1. 기존 `data` 폴더를 DSM 스냅샷/백업으로 보관합니다. 기존 `.env`와 `data`는 교체하거나 삭제하지 않습니다.
2. 앱 배포 주소의 `production-nas-update.zip`을 받아 압축을 풀고, 위 네 파일을 기존 NAS 프로젝트 폴더의 같은 위치에 넣습니다. 업데이트 ZIP 전체를 덮어써도 되지만 `.env`와 `data`는 그대로 둡니다.
3. Container Manager → 프로젝트 → 기존 프로젝트에서 **이미지를 다시 빌드하여 실행**합니다. 단순 컨테이너 재시작으로는 새 Python 파일이 적용되지 않습니다. 터미널을 쓸 경우 기존 폴더에서 `sh update.sh`를 실행하면 먼저 DB를 백업하고 다시 빌드합니다.
4. 앱을 새로고침하고 **자료 → 자료 DB**를 엽니다. 기존 사진/파일/링크/텍스트가 등록되어 있는지 확인합니다.
5. 프로젝트나 자료 탭에서 모듈 추가 → **말씀 노트**를 선택하고, 새 문서를 만든 뒤 분류 `예배`, `QT`, `동아리`를 입력해 저장·재접속을 확인합니다.

`.env`, NAS 주소, 포트, 역방향 프록시, 인증 설정은 변경하지 않습니다. 실제 NAS 적용 전에는 새 자료 DB API를 사용할 수 없으며 앱에서 서버 업데이트 안내가 표시됩니다.

## 저장/연결 동작

- 파일은 기존 `data/files/<파일 ID>`에 유지합니다. 제목·태그·속성은 SQLite의 독립된 자료 행에 저장합니다.
- 시작할 때 기존 자료를 등록하고, 프로젝트/자료 저장과 목록 조회 때 새 항목을 추가합니다. 같은 파일 ID나 같은 링크 주소는 중복 등록하지 않습니다.
- 기존 텍스트 모듈은 텍스트를 보존해 등록합니다. 원본을 강제로 바꾸지 않고 DOCX 사본으로 추가할 수 있습니다. 새 말씀 노트는 처음부터 실제 DOCX 파일입니다.
- 프로젝트/모듈의 자료 연결을 제거해도 통합 DB 항목과 파일은 유지됩니다. 자료 항목의 30일 휴지통 정리는 유지하지만 통합 DB가 보관 중인 원본 파일은 연결 항목과 함께 삭제하지 않습니다.
- `기존 자료 연결`은 같은 문서를 사용합니다. `사본으로 추가`는 새 파일 ID로 복사하여 독립적으로 편집합니다.
- 통합 DB에서는 접근 가능한 자료만 보여주며, 다른 곳에서 먼저 속성을 바꾸었으면 오래된 수정 요청은 거부합니다.

## 롤백

이 버전은 기존 테이블을 삭제하거나 파일을 변환하지 않는 추가형 마이그레이션입니다. 프런트엔드/서버를 이전 버전으로 돌려도 새 DB 테이블은 자동으로 제거하지 않습니다. 새 자료 DB에서만 생성한 문서가 이전 화면에 나타나지 않을 수 있으므로 `data` 전체를 보관하세요. 이전 서버는 통합 자료 DB의 보존 규칙을 알지 못하므로 롤백 후 자료 영구 삭제는 피하고 먼저 백업을 확인하세요.
